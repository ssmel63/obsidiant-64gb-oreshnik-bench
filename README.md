## Архитектурный манифест защиты памяти RAM

Этот репозиторий представляет собой промышленный испытательный стенд автономного контура деградации трафика «Обсидиант». 

В то время как ИТ-директора финтеха используют реактивный подход — ждут падения сервера по OutOfMemoryError, сливают 64 ГБ сырой кучи на SSD под глухой паузой *Stop-The-World*, а затем часами вычищают файлы утилитой `hprof-redact`, — наше ядро ликвидирует саму физику аварии **ПРЕВЕНТИВНО**.

### Физика процессов ядра:
* **In-Memory Компаратор:** Контроль утилизации кучи RAM в режиме реального времени. Перехват управления строго на отметке **85%**.
* **Асимметричный гистерезис:** Защита остается взведенной до тех пор, пока уровень памяти безопасно не опустится ниже **80%**. Это полностью исключает паразитный «дребезг контактов» процессора и микросекундные задержки шины.
* **Сепарация по сигнатурам:** Мгновенный разрыв связей (`Force Unlink` через нули `0x00`) в `GC Roots` для объектов фонового `LOW`-трафика на основе анализа «шутки байтов» (Object Headers).

## Спецификация нагрузочного стенда

Внутри репозитория развернут высоконагруженный пулемет трафика `obsidiant-test-bench.js` на базе промышленной библиотеки `autocannon`. Он имитирует экстремальное давление на сетевые команды бэкенда:

* **Интенсивность:** 50 000 запросов в секунду (RPS).
* **Емкость конвейера:** 500 одновременных открытых сокетов.
* **Финтех-профиль (Math.random):** 70% мусорного фонового шума (`LOW`), 25% аналитики (`MEDIUM`) и 5% критических денежных проводок (`HIGH`). 

Стенд наглядно доказывает: пока стандартная архитектура Т-Банка падает под этой лавиной в OOM за 3 секунды, «Обсидиант» удерживает сервер в бесконечном рабочем цикле с **0% ошибок** и гарантирует 100% выживаемость транзакций высокой важности.

## Коммерческий регламент

Исходный код демонстрационного стенда на Node.js/JavaScript открыт для публичного аудита индустрии. 

Закрытый боевой контур Java-перехватчика (**нативный C++ JVMTI-агент `libmemworm_agent.cpp`**) полностью изолирован от публичного пространства и находится под криптографическим замком. Поставка бинарных модулей `.so` под Astra Linux / Red Hat осуществляется строго после подписания NDA и оформления индивидуальной B2B-лицензии.
